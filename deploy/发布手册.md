# 发布手册

改完东西，照这个来。整件事只有三步：**本地看效果 → 提交 → 推送**。推完 1 分钟左右线上自动更新。

---

## 最短路径（记住这三条）

```powershell
cd C:\Users\YoY\Documents\deepseek-harness\default-workspace\myblog-dev
git add -A
git commit -m "改了什么"
git push
```

然后等一分钟，刷新 https://oao-o11o.github.io/myblog/

## 完整流程（推荐）

### 第 1 步 · 本地看效果

```powershell
npm run dev
```

如果 3000 端口已被占用（提示 "Port 3000 is in use"），说明服务已经在跑，直接打开浏览器即可：

| 看什么 | 地址 |
|---|---|
| 首页 | http://localhost:3000 |
| 文章列表 | http://localhost:3000/blog |
| 某一篇 | http://localhost:3000/blog/文章slug |
| 想法 | http://localhost:3000/notes |
| 题目 | http://localhost:3000/topics |
| 后台 | http://localhost:3000/admin/dashboard |

### 第 2 步 · 类型检查（改过代码才需要）

```powershell
npm run check
```

没输出 = 通过。改的只是文章内容可以跳过这步。

### 第 3 步 · 提交并推送

```powershell
git add -A
git status --short          # 确认改动清单里没有 .env
git commit -m "改了什么"
git push
```

或者一条命令搞定（会自动做类型检查并等待部署结果）：

```powershell
npm run publish -- "改了什么"
```

### 第 4 步 · 等部署

```powershell
gh run watch --repo oAo-o11o/myblog
```

看到 `✓ Deploy to GitHub Pages` 就是成功了，通常 40–80 秒。

### 第 5 步 · 验证线上

```powershell
$env:BASE="https://oao-o11o.github.io/myblog"; npm run verify
```

脚本会自动识别目标：

| 目标 | 跑什么 | 项数 |
|---|---|---|
| 本地 `localhost:3000` | 页面 + 权限门 + 登录 + 发文/改名/删除闭环 + 媒体接口 | 28 项 |
| 线上静态站 | 页面可达 + 文章详情页 + 配图 + 画廊数据 | 10 项 |

因为静态站没有 API 和后台，脚本不会拿接口去硬测线上，免得一堆假失败。

## 按改动类型查表

### 只改了文字（文章/想法正文）

```powershell
git add content
git commit -m "post: 改了几个字"
git push
```

### 加了图片

1. 后台 → 媒体 → 图片 → 上传（或直接把文件拖进 `public/photos`）
2. **先压缩**（原图 7–8 MB 会撑爆仓库）：

```powershell
python -c "from PIL import Image; im=Image.open('原图.jpg').convert('RGB'); im.thumbnail((1600,1600)); im.save('压缩.jpg','JPEG',quality=85,optimize=True)"
```

3. 在文章 frontmatter 里填 `media: ["文件名.jpg"]`，或在正文写 `![说明](/photos/文件名.jpg)`
4. 提交：

```powershell
git add content public
git commit -m "post: 加图"
git push
```

### 改了题目

```powershell
git add content
git commit -m "topics: 调整题目"
git push
```

### 删了内容

后台删除会移到 `content/.trash/`（不进仓库）。删完：

```powershell
git add -A
git commit -m "del: 删掉某条"
git push
```

### 改了站点设置（站名/题记/皮肤）

后台 → 站点设置 → 保存，然后：

```powershell
git add content/site.json
git commit -m "site: 改站名"
git push
```

### 改了代码或样式

```powershell
npm run check          # 类型检查，必须 0 错
npm run build          # 本地构建，必须成功
git add -A
git commit -m "ui: 改了什么"
git push
```

## 出问题怎么办

### 推送失败

**报 `Connection was reset` / `Could not connect`**
国内网络问题，等几秒重试，通常第三次就通：

```powershell
git push
```

**报 `no upstream branch`**

```powershell
git push -u origin main
```

**报 `rejected (fetch first)`**
远端有你本地没有的提交：

```powershell
git fetch origin
git reset --hard origin/main
```

⚠️ 这条会丢弃本地未提交的改动，先确认 `git status` 是干净的。

### 推上去了但线上没变

1. 打开 https://github.com/oAo-o11o/myblog/actions
2. 看最新那次是不是**红叉**
3. 点进去看 `Prepare static build` 那一步的日志

### 线上白屏 / 没样式

Actions 日志里搜 `BASE_PATH`。本地构建没设 `BASE_PATH=/myblog` 是正常的，线上由工作流注入。

### 图片 404

| 检查 | 命令 |
|---|---|
| 文件真在仓库里吗 | `git ls-files public/photos` |
| 文件名大小写对得上吗 | 前台报错的那个名字，逐字对比 |
| frontmatter 写对了吗 | 只写文件名，不要带 `/photos/` 前缀 |

```yaml
media: ["1793669101294.png"]      ✅
media: ["/photos/1793669101294.png"]   ❌ 会变成 /photos//photos/...
```

正文里插图相反，**要带前缀**：

```markdown
![说明](/photos/1793669101294.png)      ✅
```

### 后台登录失败

`.env` 里的账号密码：

```powershell
Get-Content .env
```

改完 `.env` 要重启 dev server 才生效。

## 回滚

### 撤销最近一次提交（还没推）

```powershell
git reset --hard HEAD~1
```

### 已经推了，但想撤

```powershell
git revert HEAD
git push
```

### 找回被删的内容

删除会进回收站：

```powershell
dir content\.trash                        # 看有哪些
move content\.trash\xxx__时间戳.mdx content\posts\xxx.mdx
```

更早的（回收站机制之前删的）从历史里捞：

```powershell
git log --oneline -- content/posts        # 找到删除前的那次提交
git checkout <提交号> -- content/posts
```

比如之前那 6 条示例内容，可以这样整批捞回来：

```powershell
git checkout 62d6f01~1 -- content/posts
```

### 整站回到某个版本

```powershell
git log --oneline            # 找目标提交
git reset --hard <提交号>
git push -f
```

⚠️ `-f` 会覆盖远端历史，只在确认要丢弃后续改动时用。

## 每周维护

```powershell
# 1) 仓库有没有变大（超过 800 MB 要注意）
gh api repos/oAo-o11o/myblog -q '.size' | ForEach-Object { "{0:N0} MB" -f ($_/1024) }

# 2) 本地备份一份（含图片视频）
Compress-Archive -Path content,public -DestinationPath "backup-$(Get-Date -Format yyyyMMdd).zip" -Force

# 3) 本地跑一遍完整体检
npm run check
$env:BASE="https://oao-o11o.github.io/myblog"; npm run verify
```

## 一张流程卡

```
改内容  →  npm run dev 看效果  →  git add -A  →  commit  →  push  →  等 1 分钟  →  刷新线上
改代码  →  多一步 npm run check 和 npm run build
出问题  →  先看 Actions 有没有红叉，再看日志里 Prepare static build 那一段
```
