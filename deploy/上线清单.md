# 上线清单 · CyberLog

## 一句话结论

**不一定要买服务器。** 你现在这套「文件系统当数据库 + 上传写磁盘 + ffmpeg 转码」的架构，本质是**有状态单体**：
它能跑在旧笔记本、任意 VPS、任意 Docker 主机上，但**跑不了 Vercel / Netlify / Cloudflare Pages 这类无状态平台**。

所以判断标准不是"要不要买服务器"，而是三选一：

| 路线 | 花钱 | 备案 | 国内访问 | 适合谁 |
|---|---|---|---|---|
| **A. 旧笔记本 + Cloudflare Tunnel** | **0 元** | 不需要 | 中等（取决于家宽上行） | 现在就想上线、验证阶段 |
| **B. 香港/新加坡轻量 VPS** | ¥24–40/月 | 不需要 | 40–90 ms，够用 | 怕断电、怕宿舍断网 |
| **C. 国内轻量云（阿里云/腾讯云）** | ¥99–199/首年（学生机 ¥9.9/月） | **必须 ICP 备案（7–20 工作日）** | 最快 | 长期认真做、要秒开 |

我建议：**先 A，跑两周**。这站在公网上真正的风险不是性能，是"没人看"和"你懒得更"。A 路线你今天就能上线，成本为零，等它真的有人访问、你也真的在更了，再花 ¥30/月搬去 B。

## 为什么不能直接扔 Vercel / Netlify

你的代码会在运行时写文件：

- `app/api/posts/route.ts` → `fs.writeFileSync('content/posts/*.mdx')`
- `app/api/upload/photos/route.ts` → 写 `public/photos/`
- `app/api/upload/videos/route.ts` → 写 `public/videos/` + 调 `ffmpeg`
- `app/api/about/route.ts`、`timeline/route.ts` → 改 `content/*.json`

Vercel 的 Serverless 函数文件系统**只读**（除 `/tmp`），`ffmpeg` 也不在运行时里。部署上去的表现是：前台能看，后台一点「发布」就 500。

要上这类平台，必须先换存储层（文章/JSON → KV 或数据库，图片视频 → R2/S3，转码 → 外部服务），这是**一次重构**，不是部署。现阶段不值得。

## 上线前必须做的四件事（代码层面已改好，你只需配）

| 项 | 状态 | 说明 |
|---|---|---|
| `/admin/**` 路由守卫 | ✅ 已加 `middleware.ts` | 未登录访问后台 → 307 跳登录；写接口 → 401 |
| 登录限流 | ✅ 已加 | 同 IP 10 分钟 8 次失败 → 429 |
| cookie `secure` | ✅ 已加 | `NODE_ENV=production` 时自动带 Secure |
| 上传扩展名白名单 / DELETE 防穿越 | ✅ 已加 | 只允许 jpg/png/gif/webp；filename 强制 `basename` |

你还需要在服务器上做：

```bash
# 1. 换掉密钥与弱口令（这一条不做，前面全白搭）
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # 新的 JWT_SECRET
# 编辑 .env：JWT_SECRET=<新值>、ADMIN_PASSWORD=<12 位以上>

# 2. 确认 .env 不进任何仓库 / 不打包进 zip
# 3. 后台路径可选加固：nginx 里限制 /admin 只允许你的 IP
#    location /admin { allow 1.2.3.4; deny all; proxy_pass http://127.0.0.1:3000; }
```

## 路线 A：旧笔记本 + Cloudflare Tunnel（0 元，推荐先做）

你已经跑通过一次，这次是把我们改过的版本重新上。

```bash
# 机器上（Ubuntu）
sudo apt update && sudo apt install -y nodejs npm ffmpeg

# 代码放到固定位置
sudo mkdir -p /opt/myblog && sudo chown -R $USER:$USER /opt/myblog
# 把项目拷到 /opt/myblog/app（rsync / scp / git 都行）
cd /opt/myblog/app

npm ci
npm run build

# 进程守护
sudo npm i -g pm2
pm2 start deploy/ecosystem.config.js
pm2 save
pm2 startup            # 按提示执行它输出的那行命令，实现开机自启

# 隧道
cloudflared tunnel login
cloudflared tunnel create cyberlog
cp deploy/cloudflared.yml ~/.cloudflared/config.yml   # 替换 TUNNEL_UUID
cloudflared tunnel route dns cyberlog shidagu.online
sudo cloudflared service install
```

验收：

```bash
curl -I https://shidagu.online                            # 200
curl -I https://shidagu.online/admin/dashboard            # 307 → /admin/login
curl -X POST https://shidagu.online/api/posts             # 401（未带 cookie）
```

旧笔记本要处理的现实问题：**合盖休眠**（`/etc/systemd/logind.conf` 里 `HandleLidSwitch=ignore`）、**家宽上行**（10–30 Mbps，视频首访会慢）、**断电**（配个 `pm2 startup` 重启能自恢复，但网络恢复要等）。

## 路线 B：香港/新加坡轻量 VPS（¥24–40/月，免备案）

和路线 A 的区别只有两点：换成公网 IP + 自己签证书（或者继续用 Cloudflare 代理）。

```bash
# 系统：Ubuntu 22.04 / 24.04，2C2G 起
sudo apt install -y nodejs npm ffmpeg nginx certbot python3-certbot-nginx

cd /opt/myblog/app && npm ci && npm run build
pm2 start deploy/ecosystem.config.js && pm2 save && pm2 startup

# 证书 + 反代
sudo cp deploy/nginx.conf /etc/nginx/conf.d/cyberlog.conf
sudo certbot --nginx -d shidagu.online -d www.shidagu.online
sudo nginx -t && sudo systemctl reload nginx
```

DNS 把 `shidagu.online` 的 A 记录指向 VPS IP；如果还想套 Cloudflare，A 记录指 VPS 并在 CF 里开橙色云朵即可。

选机参考：阿里云香港轻量 / 腾讯云香港轻量（国内延迟 40–70 ms，中文控制台）；Hetzner（€3.79/月，但机房在德国，延迟 200 ms+）；Vultr 东京/首尔（$6/月，延迟 60–90 ms）。

## 路线 C：国内轻量云（最快，但要备案）

流程固定，卡点在备案：

1. 买机（学生认证的话腾讯云/阿里云有 ¥9.9/月档）
2. **域名实名** + **ICP 备案**：在云厂商备案系统提交，需要身份证、手持照、网站名称（个人博客类目可过），7–20 个工作日
3. 备案通过后解析域名 → 装环境 → 同上（nginx + certbot + pm2）
4. 备案号要挂在页脚（个人站也要）

注意：**服务器在大陆 = 必须备案，跟域名后缀无关**（`.online` 也一样）。反过来说，服务器在香港/海外，或者走 Cloudflare Tunnel 回源到家里，都不涉及大陆机房，也就不需要备案。

## Docker 路线（服务器装了 Docker 时最省事）

```bash
cd /opt/myblog/app
vi .env                       # 配好密钥与密码
docker compose up -d --build
docker compose logs -f app
```

镜像里已经装了 `ffmpeg`（否则视频上传必 500），并且 `content/`、`public/photos/`、`public/videos/` 三个目录挂到了宿主机——**这三个卷就是你的全部数据**，重建镜像不会丢。

---

## 上线后：备份

```bash
chmod +x deploy/backup.sh
crontab -e
# 10 3 * * * /opt/myblog/app/deploy/backup.sh >> /var/log/cyberlog/backup.log 2>&1
```

备份内容只有四样：`content/`、`public/photos/`、`public/videos/`、`.env`。压缩后通常几十 MB（大头是原图），保留 30 天。

恢复：

```bash
tar -xzf /opt/myblog/backups/cyberlog-2026-11-02-0310.tar.gz -C /opt/myblog/app
pm2 restart cyberlog
```
