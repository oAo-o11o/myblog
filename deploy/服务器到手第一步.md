# 服务器到手：第一步做什么

你的机器 IP 是 `119.188.240.214`（中国联通山东段），**大陆机房**。这带来一个绕不过去的前提：

> **大陆服务器上的域名，必须先 ICP 备案才能通过 80/443 提供网站服务。**
> 未备案的域名指向大陆 IP，访问会被拦截（返回未备案提示或直接连接重置）。
> 直接拿 **IP + 端口**访问，通常不受影响——所以可以先用它把站跑起来。

备案由**服务器提供商**代办（需要它有 IDC/ISP 资质和备案系统）。所以第一件事不是装软件，是问客服。

## 第 0 步：三个检查（5 分钟）

### 检查 1：这台机器是什么形态

在机器上打开 PowerShell（Win+R 输入 `powershell`）：

```powershell
# 系统
systeminfo | Select-String "OS 名称","OS 版本","系统类型"

# 你是谁（有没有管理员权限）
whoami

# 网络
ipconfig
```

| 结果 | 说明 | 走哪条路 |
|---|---|---|
| `Windows Server` / `Windows 10/11` | 是**云电脑**，只有远程桌面 | **A 路线**（Windows 部署） |
| `Ubuntu` / `Debian` / `CentOS` | 是 Linux VPS | **B 路线**（我的脚本） |
| 有宝塔/其他面板 | 面板机，也能用 | B 路线，但先卸面板省内存 |

### 检查 2：问客服两句话（决定能不能用域名）

在提供商工单或客服窗口问：

```
1. 这台机器能用于公网建站吗？80/443 端口给开吗？
2. 你们能提供 ICP 备案服务号吗？帮我提交备案吗？
```

| 回答 | 意味着 |
|---|---|
| 能建站 + 能备案 | 完美，按 A/B 跑通，同时提交备案 |
| 能建站 + 不能备案 | **只能用 IP:端口 访问**，域名绑不上。要么换机，要么接受无域名 |
| 不能建站（只给远程桌面） | 这台只能当练习机，正式站得另想办法 |

### 检查 3：确认端口能不能从外面进来

在自己电脑上（不是服务器里）打开 PowerShell：

```powershell
Test-NetConnection 119.188.240.214 -Port 3000
Test-NetConnection 119.188.240.214 -Port 80
```

现在肯定都是失败（还没起服务）。等第 2 步起完服务后再测一次，**TcpTestSucceeded 变成 True 才算真的通了**。

## A 路线：Windows 云电脑上跑（按你截图，大概率是这条）

### 1. 装 Node 22

下载 **https://nodejs.org/dist/v22.11.0/node-v22.11.0-x64.msi**（或 nodejs.org 首页 LTS）
安装时勾选 **Add to PATH**。

验证：

```powershell
node -v      # v22.x
npm -v
```

### 2. 装 ffmpeg（视频上传要用）

```powershell
winget install --id Gyan.FFmpeg -e
# 装完重开一个 PowerShell
ffmpeg -version
```

`winget` 不可用时：下载 https://www.gyan.dev/ffmpeg/builds/ffmpeg-release-essentials.zip，解压到 `C:\ffmpeg`，把 `C:\ffmpeg\bin` 加进系统 PATH。

### 3. 把项目拷进去

三种方式，选一种：

```powershell
# 方式一：从你的电脑推过去（在你电脑上执行，需要服务器开了 SSH）
scp -r C:\Users\YoY\Documents\deepseek-harness\default-workspace\myblog-dev Administrator@119.188.240.214:C:\myblog

# 方式二：服务器上直接 git clone（如果项目在仓库里）
git clone 你的仓库地址 C:\myblog

# 方式三：打包→远程桌面里粘贴
#   本地：tar -czf myblog.tar.gz -x node_modules -x .next myblog-dev
#   远程桌面里解压
```

**别拷 `node_modules` 和 `.next`**，那是 Windows 本地编译的，换机器要重来。

### 4. 装依赖 + 构建

```powershell
cd C:\myblog
npm ci
npm run build
```

如果 `npm ci` 很慢，先换源（国内必要）：

```powershell
npm config set registry https://registry.npmmirror.com
```

### 5. 配密钥（不做这步等于把后台敞开）

```powershell
copy .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
notepad .env
```

`.env` 里三个值必须改：

```
JWT_SECRET=<上面生成的 64 位十六进制>
ADMIN_USERNAME=wow
ADMIN_PASSWORD=<12 位以上，别用现在的 w1a2n3g4>
```

### 6. 起服务

```powershell
npm start
```

看到 `Ready` 后，**在你自己电脑上**测：

```powershell
Test-NetConnection 119.188.240.214 -Port 3000
```

`TcpTestSucceeded : True` 才算通。不通就是防火墙没放行，继续下一步。

### 7. 放行端口

服务器上（管理员 PowerShell）：

```powershell
netsh advfirewall firewall add rule name="myblog-3000" dir=in action=allow protocol=TCP localport=3000
```

如果还是不通，说明**提供商的安全组/防火墙**也拦着，得去他们控制台放行——这一步你自己改不了，要问客服。

### 8. 让它常驻（关掉窗口也不停）

用 pm2（Windows 支持，最省事）：

```powershell
npm i -g pm2 pm2-windows-startup
pm2 start npm --name myblog -- start
pm2 save
pm2-startup install
```

以后常用命令：

```powershell
pm2 list
pm2 logs myblog
pm2 restart myblog
```

### 9. 浏览器验收

打开 **http://119.188.240.214:3000**

然后在你电脑上跑自动检查：

```powershell
cd C:\Users\YoY\Documents\deepseek-harness\default-workspace\myblog-dev
$env:BASE="http://119.188.240.214:3000"
node scripts\verify.mjs
```

27 项全绿就算跑通。

## B 路线：如果这台其实是 Linux

那就简单得多，直接：

```bash
# 本地
scp deploy/bootstrap.sh deploy/oracle-open-ports.sh ubuntu@119.188.240.214:/tmp/
# 注意：oracle-open-ports.sh 只适用于 Oracle，普通 VPS 用 ufw 即可

# 服务器
sudo bash /tmp/bootstrap.sh
sudo ufw allow 80,443,3000/tcp
```

然后按 `oracle-cloud.md` 的第四、五节：推代码 → 换 `.env` → `npm ci && npm run build` → `pm2 start` → nginx 或 cloudflared。

## 关于域名（现在就能做的决定）

| 情况 | 怎么办 |
|---|---|
| 提供商能备案 | 立刻提交（7–20 天），期间用 IP:3000 访问 |
| 提供商不能备案 | 三个选择：① 接受只有 IP；② 换到能备案的厂商（阿里云/腾讯云）；③ 放弃这台，用香港机器 |
| 暂时不想折腾 | 先 IP:3000 用着，等确定长期做再说 |

**不要做的事**：把 `shidagu.online` 的 A 记录指向这台大陆 IP。未备案的话，域名访问会被拦，还会打乱你原来 Cloudflare Tunnel 的正常访问。

## 三条硬提醒

1. **便宜"云电脑/挂机宝"的特性**：CPU 限频、带宽共享、可能半夜重启、没有快照。它适合先跑起来验证，不适合长期正式运营。
2. **Windows 不是这个项目的主场**：ffmpeg、路径、进程守护都比 Linux 麻烦。如果提供商允许「重装系统」，建议装 Ubuntu 22.04，之后所有脚本都能直接用。
3. **`.env` 里那两个密钥现在就换**。服务器一旦能从公网访问，旧密码 `w1a2n3g4` 和写死的 `JWT_SECRET` 等于门没锁。
